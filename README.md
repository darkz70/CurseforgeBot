# CurseForge → Telegram бот (на GitHub Actions)

Раз в день присылает в Telegram отчёт: сколько скачиваний за сегодня
по каждому вашему проекту на CurseForge + накопленный доход
(доход вводится вручную, т.к. публичного API для выплат у CurseForge нет).

Работает полностью на GitHub — без сервера, бесплатно (GitHub Actions).

## Что нужно сделать

### 1. Создать Telegram-бота
1. Напишите в Telegram **@BotFather** → `/newbot` → следуйте инструкциям.
2. Получите **токен бота** (вид `123456:ABC-DEF...`).
3. Напишите своему боту что угодно (`/start`), затем откройте в браузере:
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
   и найдите `"chat":{"id": ВАШ_ID, ...}` — это ваш **chat_id**.
   (Если хотите слать в группу — добавьте бота в группу и возьмите id группы оттуда же.)

### 2. Получить API-ключ CurseForge
1. Зарегистрируйтесь на https://console.curseforge.com/
2. Создайте API-ключ (раздел API Keys).
3. Узнайте **ID ваших проектов**: откройте страницу проекта на curseforge.com,
   ID указан в правой колонке "About Project" (поле "Project ID"),
   либо через сам API.

### 3. Загрузить этот проект на GitHub
1. Создайте новый репозиторий на GitHub.
2. Загрузите туда все файлы из этой папки (через git или "Add file → Upload files").

### 4. Настроить секреты репозитория
В репозитории: **Settings → Secrets and variables → Actions → New repository secret**

Добавьте:
| Имя | Значение |
|---|---|
| `CURSEFORGE_API_KEY` | ваш API-ключ CurseForge |
| `TELEGRAM_BOT_TOKEN` | токен бота из BotFather |
| `TELEGRAM_CHAT_ID` | ваш chat_id |

### 5. Указать свои проекты
Откройте `config.json` и замените `id` и `name` на свои проекты:
```json
{
  "projects": [
    { "id": 123456, "name": "Название проекта" }
  ]
}
```
Либо, без редактирования файла — задайте переменную репозитория
(**Settings → Secrets and variables → Actions → Variables**)
`CURSEFORGE_PROJECT_IDS` со значением вида `123456,234567`.

### 6. Проверить
Перейдите в **Actions → Daily CurseForge report → Run workflow**,
чтобы запустить отчёт вручную и убедиться, что сообщение пришло в Telegram.

После этого бот будет сам присылать отчёт каждый день в 09:00 МСК
(время можно поменять в `.github/workflows/daily_report.yml`, поле `cron`).

## Как записывать доход
Доход CurseForge не отдаёт по API — вводите его руками:

**Actions → Add money → Run workflow** → укажите сумму и (опционально) комментарий.
Бот сразу подтвердит запись в Telegram, а в следующем ежедневном отчёте
эта сумма попадёт в раздел "💰 Доход".

## Структура проекта
```
.github/workflows/daily_report.yml   — почасовой отчёт по скачиваниям
.github/workflows/daily_digest.yml   — ежедневный дайджест (21:00 UTC)
.github/workflows/weekly_report.yml  — еженедельный PDF-отчёт (вс 20:00 UTC)
.github/workflows/milestone_check.yml— круглые числа скачиваний (каждые 30 мин)
.github/workflows/version_check.yml  — проверка новых версий мода (каждые 30 мин)
.github/workflows/category_rank.yml  — рейтинг мода в категории (раз в день)
.github/workflows/server_status.yml  — доступность CurseForge/GitHub (каждые 15 мин)
.github/workflows/download_totals.yml— сводка «сколько всего скачиваний» (вручную)
scripts/download_totals.py           — текущее число скачиваний по модам и платформам
scripts/daily_report.py              — логика отчёта (скачивания + доход)
scripts/daily_digest.py              — дайджест дня
scripts/weekly_report.py             — недельный PDF с графиками
scripts/milestone_check.py           — майлстоуны скачиваний
scripts/version_check.py             — уведомления о новых версиях мода
scripts/category_rank.py             — рейтинг в категории по скачиваниям
scripts/server_status.py             — мониторинг доступности сервисов
config.json                          — список проектов + настройки
data/                                — состояние (история, ранги, версии — авто)
```

## Новые фичи (добавлены)

| Фича | Как работает |
|---|---|
| 📈 PNG-график за 12 часов | Картинка с приростом скачиваний по часам, шлётся каждый прогон (если данных хватает) |
| 🌅 Первое скачивание дня | Время и величина первого прироста за сутки |
| ↑↓ Динамика | Стрелка — этот час лучше/хуже предыдущего |
| 📊 Среднее в день | Средний прирост за полностью завершённые дни (до 14 дн.) |
| 🔇 Антиспам | Если у проекта за час +0 — для него выводится только короткая строка без статистики (остальные проекты и общий отчёт всё равно отправляются) |
| 🚀 Вирусный рост | Если прирост за час в N раз больше обычного (настройка `viral_multiplier`) — отдельный алерт |
| 🏅 Топ-10 рекордных часов | Список лучших часов по приросту за всю историю |
| 🎉 Новые версии мода | Уведомление в Telegram, когда на CurseForge выходит новая версия (каждые 30 мин, `version_check.yml`) |
| 📦 Сколько всего скачиваний | Сводка по каждому моду на CurseForge + общий итог; по кнопке **Actions → Download totals → Run workflow** (`download_totals.yml`) |
| 🏆 Рейтинг в категории | Позиция мода в категории CurseForge по скачиваниям; уведомление при изменении места (раз в день, `category_rank.yml`, нужен `CURSEFORGE_API_KEY`) |
| 🔴 Доступность сервисов | Алерты, если CurseForge или GitHub легли или восстановились (каждые 15 мин, `server_status.yml`) |

## 🆕 Уведомления о новых версиях мода

Теперь бот умеет и это: как только на CurseForge выходит новая
версия мода — в Telegram сразу приходит уведомление с названием версии,
игровыми версиями и changelog.

- **Скрипт:** `scripts/version_check.py`
- **Workflow:** `.github/workflows/version_check.yml` — каждые 30 минут
- **Состояние:** `data/versions.json` (какие файлы/версии уже известны)

При первом запуске бот «тихо» запоминает текущую последнюю версию и присылает
подтверждение «✅ Бот подключен». Дальше уведомляет только о действительно новых
версиях — дублей нет. Если отправить не удалось, состояние не сохраняется, и
уведомление уйдёт при следующем прогоне.

Работает и без ключа CurseForge (через публичный CFWidget), но с
`CURSEFORGE_API_KEY` берёт точные данные и полные чейнджлоги.

Проверить вручную: **Actions → New mod version check → Run workflow**
(или локально: `python scripts/version_check.py --dry-run` — напечатает
сообщения в консоль вместо отправки).

Настройки — в `config.json`:
```json
{
  "viral_multiplier": 4,
  "viral_min_absolute": 20,
  "send_png_chart": true,
  "png_chart_hours": 12,
  "top_records_count": 10
}
```

Зависимость для PNG-графиков — `matplotlib`, добавлена в `requirements.txt`
и в шаг установки в workflow.

 (команды /stats, /money и т.д. в любой момент)
GitHub Actions не умеет работать 24/7 и слушать сообщения — только по расписанию
или вручную. Для бота, который отвечает на команды сразу, понадобится
постоянно работающий процесс (например, бесплатный тариф Railway / Render / VPS).
Скажите, если такой вариант нужен — соберу отдельно.
